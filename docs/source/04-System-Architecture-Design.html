1. Architecture overview

Aj Smart Biz is a shared-database, shared-schema multi-tenant system. One Express API owns all data and business rules. Four kinds of client consume it, each through its own route module with its own guard.

Rule: the guard belongs to the module, not to the route. Each consumer has one composed router (src/modules/*). Its scope guard is applied once when it is mounted, so a route added inside a module cannot accidentally be left unprotected.

5. Component design — Next.js websites

Tenant themes

  • middleware.ts resolves the domain (?domain= → forwarded host → TENANT_DOMAIN → cookie) into header x-tenant-domain.
  • getCompanyDetails() calls /theme/company-details?domain= (no-store), memoised per render.
  • Server Components by default; 'use client' only for interactivity; siteCompany() strips the catalogue from client props.
  • Server Actions in app/actions/ for orders, enquiries, bookings, reviews and account; customer token in httpOnly cookie.
  • /uploads/[...path] route proxies images; /api/track proxies the beacon.

Product website

  • lib/api.ts is the only file that talks to the API.
  • getSite() = /website/bootstrap, revalidated every 300 s, retried with back-off, last good response kept in memory and on disk.
  • Throws only if the API has never answered → ApiDownNotice.
  • One server action: submit-enquiry.ts.

6. Multi-tenancy

6.1 Isolation model

  • Every tenant-owned row carries companyId; tenant tables are prefixed company_.
  • In /admin the company is read from the token (req.auth.companyId), never from the URL or body.
  • The same routers mounted under /super-admin/companies/:companyId/… honour the URL parameter — the super admin may address any tenant.
  • Look-ups are scoped by company; a foreign id returns 404, revealing nothing.

6.2 Tenant resolution by domain

6.3 Branch awareness

A domain pinned to a branch (sub_company_id) serves that branch's logo, favicon, theme colours, slides, About, figures, team, gallery, features and Contact settings, falling back to the company-wide row where the branch has none. Theme colours merge per key: branch → company → preset theme.

7. Authentication & authorisation

ScopeIssued byToken carriesGuards
super_adminPOST /auth/super-admin/loginid, scopeauthenticate + superAdminOnly on /super-admin
adminPOST /auth/admin/loginid, scope, companyIdauthenticate + adminOnly, then requirePermission(slug, action)
customerPOST /theme/auth/verify (OTP)id, scope, companyIdauthenticate + customerOnly on /theme/me
  • authenticate reloads the principal from the database on every request and rejects inactive/deleted users and inactive companies — a disabled account is locked out immediately, not at token expiry.
  • RBAC: role_permissions (role × menu × canView/canCreate/canEdit/canDelete/canExport). The main admin (isCompanyAdmin) and super admins bypass it.
  • /auth/me returns the permission map and menu tree; menus are dropped when the plan does not grant their functionality (MENU_FUNCTIONALITY), and children in MENU_INHERITS_PARENT follow the parent's permission.
  • The Admin UI mirrors the API: permissionGuard on routes, *appCan on buttons — but the API is the enforcement point.

9. Key flows

9.1 Website page render

  1. Request reaches the design's container via nginx; middleware sets x-tenant-domain.
  2. Layout and page call getCompanyDetails() (one API call per render thanks to fetch memoisation).
  3. Guard chain: API unreachable → ServiceUnavailable; unresolved → CompanyNotFound; service.active=false → PlanNotice; feature absent → 404.
  4. Sections render from the payload; brand colours become CSS variables on <body>.

9.2 Place an order

  1. Client cart → Server Action submitOrder → POST /theme/orders with domain, product ids, quantities, contact, optional address id and Bearer token.
  2. order.service checks entitlement (products + orders active, route usable), prices every line from the catalogue, snapshots lines and address, assigns ORD… number, stores pending.
  3. Response returns number, total and the WhatsApp text / payment link; the browser opens the hand-off.

9.3 Provision a company

One transaction in company.service.createCompany: company → head-office branch (CODE-HO) → optional domain → system role + full permissions → three default slides → main admin (generated password returned once) → optional subscription activation + transaction.

9.4 Subscription sweeper

runDueSubscriptions() runs at boot, hourly, and on demand: activates due pending terms, renews autoRenew terms at end, expires terms past endDate + graceDays, writing a subscription_events row for each move.

10. State machines

Subscription (SUBSCRIPTION_TRANSITIONS)

pending   → active | cancelled
active    → suspended | expired | cancelled | superseded*
suspended → active | expired | cancelled
expired, cancelled, superseded: final
* superseded only through a plan change

Order (ORDER_TRANSITIONS)

pending → confirmed → packed → dispatched → delivered
any non-terminal → cancelled
confirmed: reserve stock · dispatched: issue stock
cancelled: release or return stock
payment: unpaid → paid → refunded (paid → unpaid allowed)

Booking (BOOKING_TRANSITIONS)

requested → accepted | declined | cancelled
accepted  → completed | cancelled
requested and accepted hold the slot

Invoice

draft → issued → cancelled
draft: editable, deletable
issued: stock deducted, payments unpaid|partial|paid
cancelled: stock returned

12. Architecture decisions (ADR summary)

#DecisionReason
1Shared schema with companyId, not a database per tenantSmall tenants, many of them; one sync, one backup, one deploy.
2One deployment per website design, tenant resolved by hostOnboarding without builds; designs upgrade for all tenants at once.
3Company from token, never from clientMakes cross-tenant access impossible by construction.
4Snapshots for plans, order lines, addressesHistory must not change when sources are edited.
5Soft delete everywhere (except ledgers/switches)Recoverability; uniqueness checked in services instead of DB indexes.
6Stock = ledger + running total in one transactionTruth and speed; drift traceable via balanceAfter.
7Sequelize alter-sync instead of migrationsSpeed of iteration; trade-off — production schema changes need care (see Document 07).
8No UI/chart libraries in consolesSmall bundles, one design system, hand-written SVG charts starting at zero.
9Constants file as the single catalogueAdding a feature or enum is one entry; validators, Swagger and UIs read it.
