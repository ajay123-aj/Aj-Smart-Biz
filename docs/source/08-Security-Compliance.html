1. Security principles

  1. Derive, don't trust. Tenant, prices, addresses and the customer's identity are derived on the server; the client sends ids and quantities only.
  2. Guard at the module. Scope guards are mounted once per route module, so new routes inherit protection.
  3. Absent, not hidden. A feature that is not live is null in the payload — not hidden with CSS — so a lapsed tenant's data never appears in page source.
  4. Fail closed. No plan means blocked, not unlimited; unknown hosts get platform defaults, not errors that confirm existence.

3. Tenant isolation

  • Admin routes read companyId from the token; URL/body company ids are ignored for admins.
  • Every query is scoped by company; another tenant's id returns a generic 404.
  • Uploads can be deleted only within the caller's own company.
  • Public tenant endpoints resolve the company from the host; an unknown/inactive host returns platform defaults, preventing enumeration.
  • Customers are unique per company — the same phone at two shops is two unrelated accounts.
  • Platform-wide views (cross-tenant leads/customers) exist only under /super-admin and are read-only.

5. Uploads and storage

  • Image MIME types only; favicons verified by ICO magic bytes.
  • Random filenames ({base36 time}-{hex}.ext) in fixed folders; no user-chosen paths.
  • /uploads served with Content-Security-Policy: default-src 'none' and nosniff, so an SVG cannot execute script.
  • Per-company storage quota enforced on upload; ledger in company_files; replaced images deleted.
  • The theme /uploads proxy rejects .. path segments.

9. Gaps and recommendations

  1. Connect an SMS gateway before enabling customer accounts on any live tenant; unset CUSTOMER_OTP_DEV_CODE in production.
  2. Implement refresh-token rotation in the consoles (refresh token is stored but unused), or shorten access tokens.
  3. Consider moving console tokens from localStorage to httpOnly cookies, and add MFA for super admins.
  4. Add account lockout / progressive delay per user, not only per IP.
  5. Add CAPTCHA or proof-of-work to public enquiry, review and order forms.
  6. Remove the default super-admin password from .env.development history and ensure production uses unique secrets.
  7. Add audit logging for admin actions beyond subscriptions and stock (who changed prices, roles, permissions).
  8. Automated dependency scanning (npm audit / Dependabot) and an automated test suite in CI.
  9. Encrypted, off-site backups of MySQL and the uploads volume with restore drills.
