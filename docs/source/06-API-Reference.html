1. Conventions

Envelope

{ "success": true,  "message": "Branch list fetched successfully",
  "data": [ ... ],  "meta": { "total": 42, "page": 1, "limit": 10, "totalPages": 5, "hasNext": true } }

{ "success": false, "message": "Validation failed",
  "errors": [ { "field": "email", "message": "\"email\" must be a valid email", "in": "body" } ] }

Authentication

Authorization: Bearer <accessToken>. Login returns { accessToken, refreshToken, expiresIn, user }. Scopes: super_admin, admin, customer.

List queries

?page=1&limit=10&search=&status=active&sortBy=name&sortOrder=asc plus resource filters. limit ≤ 200. sortBy is allow-listed per resource.

Common sub-routes

PATCH /:id/statusToggle { status: "active" | "inactive" }
PATCH /reorderSend the whole ordered id list; sets sequence
GET /dropdown[{ id, name }] for selects
POST /:id/restoreUndo a soft delete
DELETE /:idSoft delete

Status codes

200 OK · 201 Created · 202 Accepted (AI job) · 400 validation/business rule · 401 unauthenticated · 403 forbidden (permission) · 404 not found (including other tenants' ids) · 409 conflict · 429 rate limited · 500 server error.
